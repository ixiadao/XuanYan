# 玄言反馈指南

玄言编译器源码保持私有。公开仓库用于下载正式技术预览、阅读规范和提交反馈，不接收
编译器源码拉取请求。`editors/vscode` 是采用 MIT 许可的独立外围客户端；它只复用
已发布的 `xuanyan-lsp`，不包含编译器或语言服务器的 Rust 实现源码。

## 缺陷报告

使用“缺陷报告”表单，并提供：

- `xuanyan --version` 的完整输出；
- Windows 或 Linux 的版本和 x86_64 架构；
- 实际执行的玄言命令；
- 可以独立运行的最小 `xuan.toml` 和 `.xy` 源码；
- 完整中文诊断、标准输出、标准错误和退出状态；
- 期望行为以及问题是否每次出现。

删除业务数据、令牌、密码、私有地址和无权公开的源码。无法公开源码时，先把问题缩小
为不包含业务内容的最小复现。

## 语言与工具建议

使用“语言与工具建议”表单，先说明真实问题，再说明建议。涉及语法、所有权、标准库
公开名称或可观察语义时，应同时给出：

- 当前写法为何无法清晰表达；
- 最小玄言示例；
- 期望的中文名称或语法；
- 与同领域现有名称和语义是否冲突；
- 可以暂不实现的范围。

问题讨论和投票不是语言规范。只有正式更新的语言参考和发布说明构成公开承诺。

## 安全问题

可能导致任意代码执行、路径越界、权限绕过、敏感信息泄露或发布资产被替换的问题，
不要创建公开 Issue。公开分发仓库启用 GitHub 私密安全报告后，通过该入口提交。

## 反馈权利

提交者保留自己源码和原创内容的权利。为使问题能够被复现、引用和修复，公开提交的
反馈按技术预览专有许可中的反馈条款处理。公开入口不是保密渠道。
