# 玄言技术预览已知限制

## 平台

| 等级 | 平台 | 当前范围 |
| --- | --- | --- |
| 完整支持 | Windows x86_64、Linux x86_64 | 提供公开工具链归档和完整原生产品门禁 |
| 技术预览 | Android arm64-v8a、HarmonyOS NEXT arm64-v8a | 只接受 `android-arm64-v8a` 与 `harmonyos-next-arm64-v8a` 两个固定移动平台名称，生成 AArch64 ELF 共享库；官方 JNI、Node-API 和移动宿主适配保持私有并通过真机门禁 |
| 预留，未发布 | macOS x86_64、iOS | macOS 只有 Mach-O 结构和基础产物测试，iOS 尚未接入；都不属于当前发布承诺和四平台验收门禁 |

- 不公开移动平台壳源码，不提供商店签名 APK/HAP、自动移动 SDK 安装、任意
  target triple、其他移动 ABI 或跨平台 UI 框架。
- 发布归档只提供每用户离线安装与卸载脚本，不提供系统范围安装、操作系统信任链
  代码签名、自动更新或降级机制。
- Windows 桌面网页窗口需要系统 WebView2 Runtime。
- Linux 桌面窗口需要 GTK3，桌面网页窗口还需要 WebKitGTK 4.1。
- Linux 使用 `获取HTTPS响应` 需要系统提供 `libcurl.so.4` 和可用 CA 信任存储。

## 语言与兼容性

- 技术预览不承诺旧语法、旧包格式、旧诊断或旧公共 API 兼容。
- `运行`、`构建` 和 `测试` 只使用玄言独立原生代码生成器，不存在 Rust 后端、
  解释器或第二编译管线回退。
- 所有目标复用同一语言语法和语义；平台无关的 `检查` 通过不代表每个目标都能生成
  该程序。目标后端未覆盖的组合在构建时报告 `NBE001`。
- 已接入平台能力的权限、文件、网络、证书或系统运行库失败按公开返回值或 `结果`
  处理，不作为编译期平台不支持。
- 当前不提供条件编译、目标查询、用户构建标签或按文件名自动选择平台源码。
- v0.1 规范清单中的接受程序在 Windows/Linux 持续经过真实原生构建与执行门禁。
- 移动 AArch64 支持无载荷和单载荷用户枚举；载荷限于空、整数、布尔、字符、字节、
  字符串、标准可选/结果和不超过 7 个机器字的固定结构体。列表、闭包及其他资源
  载荷仍报告 `NBE001`。
- 移动列表支持整数、布尔、字符、字节、字符串以及不超过 7 个机器字的固定结构体
  和用户枚举；嵌套列表、闭包、其他资源及更大元素布局报告 `NBE001`。
- 移动 AArch64 闭包支持复制捕获一个整数、接收一个整数参数并返回整数；其他捕获
  数量、参数签名、返回类型或闭包布局报告 `NBE001`。
- 超出当前原生类型、布局、宿主 ABI、借用或投影范围的组合报告 `NBE001`。
- 语言参考是已落地语法和可观察语义的事实来源；问题或建议本身不会自动成为规范。

## 包与工具

- 只支持 `xuan.toml` 和本地路径依赖；路径可以相对于当前包，也可以是当前平台的
  完整绝对路径。绝对路径与机器安装位置绑定；不提供环境变量展开、隐式包搜索、
  远程包仓库、包发布或依赖锁文件。
- 标准库、HTTP 包和 JSON 包以可见玄言源码分发，使用和修改受技术预览专有许可约束。
- 提供 VS Code 扩展；它要求本机已有完整玄言工具链，不自动下载工具链。扩展提供
  语言服务和公开 CLI 五命令工作流，但不包含调试器。当前不提供 JetBrains 或其他
  编辑器插件。
- 不提供完整 IDE、调试器、性能分析器、代码覆盖率或项目脚手架。

## 运行时与标准库

- 当前网络能力包含同步阻塞 TCP、有界 HTTPS 请求和 HTTP/1.1 服务端。TCP 客户端
  支持通过系统地址解析器使用主机名；`发送HTTPS请求` 支持大写 ASCII 方法、原始
  CRLF 请求头和最多 16 MiB 的请求正文，使用系统证书信任链并返回最终状态码、
  最终地址、最多 64 KiB 的最终响应头与最多 16 MiB 的响应正文原始字节。HTTP `4xx`
  与 `5xx` 仍属于成功响应。
- HTTPS 请求不提供重定向控制、流式读取、HTTP/2、HTTP/3、WebSocket
  或公开异步运行时。
- `packages/http` 是 HTTP/1.1 服务端基础包，并提供对标准库 HTTPS 请求的薄转发和
  响应头首值查询；它不是带连接池、Cookie、重定向策略或异步执行的完整客户端。
- `packages/json` 提供严格完整文本解析、事件列表导航与文本生成；对象成员和数组
  元素查找按事件列表顺序扫描。它不提供结构体或枚举自动序列化、流式或增量接口、
  JSON5、Schema、DOM 或随机访问树。解析输入和生成输出上限均为 1 MiB，嵌套上限
  为 128 层，项目上限为 4096；数字以严格原始十进制文本传递。
- 标准库不提供 GBK 等传统字符编码转换；面向文本的接口以有效 UTF-8 为边界。
- 不提供用户 FFI、动态库绑定、通用反射或运行时代码加载。
- 桌面能力是阻塞式顶层窗口、确认框和网页窗口基座，不是完整原生控件框架。
- HTTP 包有明确的请求头、正文、分块元数据和空闲时间上限，不面向无限流式负载。

## 发布与支持

- 技术预览按现状提供，不承诺服务等级、长期支持周期或生产环境适用性。
- 发布归档附带 SHA-256 校验文件；`SHA256SUMS` 使用独立 Ed25519 发布密钥签名。
- 该签名验证 GitHub 发布归档是否来自玄言发布密钥，不等同于 Windows
  Authenticode 或 macOS notarization。
- 编译器不包含遥测、账户登录或远程激活；使用本地包时不需要连接玄言服务器。
- 安全问题不应包含在公开缺陷中，应使用公开仓库启用的私密安全报告入口。
